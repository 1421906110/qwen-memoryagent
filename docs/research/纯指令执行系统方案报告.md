## 一、现状与痛点

### 1.1 当前 AI Agent 的问题

| 问题 | 表现 |
|------|------|
| 成本高 | 每次调用大模型API都要付钱，高频使用每月数百到数千元 |
| 响应慢 | 大模型推理需要1-10秒，简单操作也要等 |
| 不稳定 | 模型会幻觉、会瞎编、会理解错指令 |
| 资源重 | 本地跑模型需要 GPU，云端调 API 需要网络+费用 |
| 维护烦 | 大模型版本更新可能改变行为，需要持续适配 |

### 1.2 小企业的真实痛点

大量小企业每天需要重复执行固定的操作，但缺乏自动化手段：

| 行业 | 重复操作 | 当前方式 | 痛点 |
|------|---------|---------|------|
| 小电商 | 查库存、打单、发物流信息 | 人工每天登录操作 | 费时、易错 |
| 代账/财务 | 拉流水、生成日报 | 手动导出+整理 | 每天固定耗时1-2小时 |
| 小工厂 | 检查设备状态、导出产量 | 专人巡检记录 | 人力成本高 |
| 社区运营 | 定时发内容、检测链接可用性 | 人工盯着+手动操作 | 不能24小时在线 |
| 小团队 | 备份数据、监控服务器 | 手动或写脚本 | 有技术门槛 |

**核心矛盾：** 这些操作逻辑固定、需求量小、定制化强——买大厂的SaaS不划算，自己开发没技术能力。

## 二、方案目标

### 2.1 一句话定义

> **不做"什么都会"的AI，做"说什么干什么"的指令执行器。**

### 2.2 核心能力

- **零大模型**：不调用任何 LLM API，不依赖 GPU，不需要加载模型
- **纯指令驱动**：用户发指令 → 匹配规则 → 直接执行 → 返回结果
- **模块化积木**：每个功能是一个独立模块，可以单独开发、单独售卖
- **多通道接入**：支持微信、网页、API等多种入口
- **低成本运行**：一台低配服务器甚至树莓派就能跑

### 2.3 核心原则

```
指令明确 → 100%执行
指令模糊 → 明确提示，不瞎猜
不认识的指令 → 直接拒绝，不编造
执行失败 → 报原始错误，不美化
```

## 三、核心理念

### 3.1 大模型 vs 纯指令系统对比

| 维度 | 大模型 Agent | 纯指令系统 |
|------|-------------|-----------|
| 推理成本 | **每次几分到几毛** | **零** |
| GPU 需求 | 必需（4-16GB 显存） | **完全不需要** |
| 响应速度 | 1-10秒 | **毫秒级** |
| 执行确定性 | 可能幻觉、会跑偏 | **100%确定** |
| 可调试性 | 黑盒，难排查 | **白盒，每一行都可查** |
| 扩展能力 | 加功能需要调prompt/微调 | **加一个模块就行** |
| 运行资源 | 4-16GB 内存起 | **几十MB内存** |
| 适合场景 | 开放域、创意类 | **固定流程、重复操作** |

### 3.2 积木式架构

### 4.2 模块技术实现

每个模块就是一个独立的 Python 文件或 Shell 脚本，遵循统一接口：

```python
# /modules/screenshot.py — 示例模块
def execute(params: dict) -> dict:
    """
    参数：
    - region: 可选，截图区域 "1920x1080+0+0"
    - output: 可选，输出路径
    
    返回：
    - success: bool
    - message: str
    - file_path: str (图片路径)
    """
    import subprocess, os
    output_path = params.get('output', '/tmp/screenshot.png')
    subprocess.run(['screencapture', '-x', output_path])
    return {
        'success': True,
        'message': '截图成功',
        'file_path': output_path
    }
```

**模块规范（强制）：**

| 要求 | 说明 |
|------|------|
| 输入 | 统一的 params dict |
| 输出 | 统一的 result dict（success/message/data）|
| 无外部依赖 | 只使用标准库或系统自带命令 |
| 幂等性 | 同一参数执行多次结果一致 |
| 超时控制 | 每个模块必须有超时机制（默认30秒） |
| 错误处理 | 明确返回错误信息，不抛未处理异常 |

### 4.3 指令路由引擎

核心匹配逻辑极其简单，甚至不需要正则引擎：

```python
# 指令注册表
COMMANDS = {
    "/screenshot":    {"module": "screenshot",    "desc": "截取当前屏幕"},
    "/screenshot:region": {"module": "screenshot", "params": {"region": True}, "desc": "截取指定区域"},
    "/compress":      {"module": "compress",     "desc": "压缩文件/文件夹"},
    "/download":      {"module": "download",     "desc": "下载URL指向的文件"},
    "/timer":         {"module": "timer",        "desc": "设置定时提醒"},
    "/cron":          {"module": "cron",         "desc": "设置周期任务"},
    "/search":        {"module": "search",       "desc": "搜索文件"},
    "/help":          {"module": "help",         "desc": "显示所有可用指令"},
}

def route(message: str):
    parts = message.strip().split()
    cmd = parts[0]
    args = parts[1:] if len(parts) > 1 else []
    
    if cmd not in COMMANDS:
        return {"success": False, "message": f"未知指令。输入 /help 查看所有可用指令"}
    
    module_info = COMMANDS[cmd]
    return execute_module(module_info['module'], args)
```

### 4.4 基于 Hermes 的实现方式（最快路径）

不需要从头搭建，直接在 Hermes 上做一套**纯执行 Skill 模板**：

```yaml
# ~/.hermes/skills/executor/SKILL.md 示例
name: executor
type: pure-execution  # 标记：不经过大模型
trigger: 用户消息以 / 开头

rules:
  - pattern: "/screenshot"
    action: terminal("screencapture -x /tmp/screen.png; echo done")
    response: 发回图片文件
    
  - pattern: "/compress {path}"
    action: terminal("zip -r /tmp/archive.zip {path}")
    response: 发回压缩包
```

Hermes 后台判断：如果用户消息以 `/` 开头 → **跳过所有大模型推理** → 直接匹配执行 → 返回结果。

## 五、模块开发流程

### 5.1 为小企业定制模块的标准流程

```
客户需求 → 分析操作流程 → 开发模块 → 测试 → 部署 → 收款
```

**详细步骤：**

**Step 1：需求沟通（30分钟）**
- 客户描述每天重复做的操作
- 明确输入（需要什么信息）和输出（得到什么结果）
- 确定触发方式（定时/手动/事件驱动）

**Step 2：分析拆解（30分钟）**
- 把操作拆解为具体命令步骤
- 确认哪些可以自动化（90%以上可以）
- 评估开发难度（通常1个模块0.5-2天）

**Step 3：开发（0.5-2天）**
- 写模块代码（遵循统一接口）
- 写测试用例
- 在本地环境验证

**Step 4：部署（30分钟）**
- 放到客户指定的服务器或我们的服务器
- 配置触发条件（微信指令/定时任务）
- 验证端到端流程

**Step 5：交付+收款**
- 提供使用说明（3-5条指令，简单到傻子都会用）
- 月付/年付，按月收费

### 5.2 示例：为某电商定制的"每日销售额播报"模块

```python
# 需求：每天上午10点，自动拉取各平台销售额，汇总发到微信群
# 模块：daily_sales_report

def execute(params):
    import subprocess, json
    
    # 1. 调电商平台API拉数据
    result = subprocess.run([
        'curl', '-s', 
        f'https://api.shop.com/v1/sales?date={params["date"]}',
        '-H', f'Authorization: Bearer {params["api_key"]}'
    ], capture_output=True, text=True, timeout=30)
    
    sales_data = json.loads(result.stdout)
    
    # 2. 汇总成简洁消息
    summary = f"📊 {params['date']} 销售日报\n"
    summary += f"总销售额：¥{sales_data['total']}\n"
    summary += f"订单数：{sales_data['orders']}\n"
    summary += f"客单价：¥{sales_data['avg_order']}"
    
    # 3. 发到企业微信群
    subprocess.run([
        'curl', '-s', '-X', 'POST',
        params['webhook_url'],
        '-H', 'Content-Type: application/json',
        '-d', json.dumps({"msgtype": "text", "text": {"content": summary}})
    ], timeout=10)
    
    return {"success": True, "message": "日报已发送"}
```

**客户看到的效果：** 每天10点微信群自动弹出销售数据，不需要任何人操作。
