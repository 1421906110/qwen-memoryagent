## 一、方案定位与核心原则

### 一句话定义

> **不做"什么都会但靠不住"的AI，做"只会几件事但绝对可靠"的指令执行器。**

### 核心原则

```
输入明确指令 → 100% 执行
输入模糊意图 → 自动映射到最匹配的指令（不用大模型），匹配不上则友好提示
不认识的请求 → 明确告知不支持，不瞎编、不猜
执行失败     → 返回可读的错误信息，不抛原始堆栈给用户
不依赖任何大模型 → 零 LLM API 调用、零 GPU、零模型文件
```

### 与"大模型 Agent"的核心差异

| 维度 | 大模型 Agent | 纯指令系统 |
|------|-------------|-----------|
| 推理成本 | 每次几分到几毛 | **零** |
| GPU 需求 | 必需 | **完全不需要** |
| 响应速度 | 1-10秒 | **毫秒级** |
| 执行确定性 | 可能幻觉、会跑偏 | **100% 确定** |
| 可调试性 | 黑盒，难排查 | **白盒，每一行可查** |
| 运行资源 | 4-16GB 内存起 | **几十 MB 内存** |
| 联网需求 | 需要访问 LLM API | **任意网络环境，能通就行** |
| 适合场景 | 开放域、创意类 | **固定流程、重复操作** |

## 二、为什么不依赖大模型

### 2.1 大模型在这个场景是"过度杀伤"

小企业自动化的本质：**固定操作流程的机械化执行**。

- 查库存 → 调 API → 格式化输出 → 发消息
- 定时备份 → 执行压缩 → 传到对象存储 → 发通知
- 检测网站 → curl 检查状态码 → 异常告警

这些操作一个 `if-else` 就能解决的问题，每次花几分钱调大模型是**资源错配**。

### 2.2 大模型带来的反而是问题

| 问题 | 表现 |
|------|------|
| 成本 | 高频使用每月数百到数千元 |
| 响应慢 | 简单操作也要等推理时间 |
| 不可靠 | 幻觉、理解错、指令走偏 |
| 依赖 | 断网/API故障就停摆 |
| 维护 | 模型升级可能改变行为 |

### 2.3 不加 LLM ≠ 不能理解自然语言

这是关键认知。后面会讲——**用极轻量的本地 NLP 技术（TF-IDF + 关键词匹配 + 意图分类）**，不需要大模型也能让用户说人话。后面第4节详细说。

### 3.2 架构关键设计决策

| 决策 | 选择 | 理由 |

### 3.3 核心路由引擎（30行）

```python
"""指令路由引擎 — 核心不超过 50 行"""

import json, shlex, subprocess, importlib
from pathlib import Path

MODULES_DIR = Path("/opt/executor/modules")

def route(raw: str) -> dict:
    """入口：接收原始用户消息，返回执行结果"""
    raw = raw.strip()
    if raw.startswith("/"):
        return _execute_cmd(raw)         # 精确命令
    else:
        return _execute_nlu(raw)         # 自然语言映射

def _execute_cmd(raw: str) -> dict:
    parts = shlex.split(raw)
    cmd, args = parts[0], parts[1:]
    module = _find_module(cmd)
    if not module:
        return {"ok": False, "msg": f"'{cmd}' 不存在，输入 /help 查看可用指令"}
    return _run_module(module, {"args": args})

def _find_module(cmd: str):
    """在 modules/ 下找匹配的模块（支持 /screenshot 或 screenshot）"""
    cmd = cmd.lstrip("/")
    mod_path = MODULES_DIR / f"{cmd}.py"
    return mod_path if mod_path.exists() else None

def _run_module(mod_path: Path, params: dict) -> dict:
    """子进程隔离执行模块"""
    input_json = json.dumps(params)
    result = subprocess.run(
        ["python3", str(mod_path)],
        input=input_json, capture_output=True, text=True,
        timeout=30
    )
    if result.returncode != 0:
        return {"ok": False, "msg": f"执行失败: {result.stderr.strip()}"}
    return json.loads(result.stdout)
```

## 四、轻量 NLU 映射层（关键差异化）

这是本方案与传统"纯命令"方案的核心区别——**不需要大模型，也能让用户说人话**。

### 4.1 为什么不直接用正则

- "截个图"、"帮我截屏"、"screenshot" → 都要映射到 screenshot 模块
- "明天9点提醒我开会"、"设个提醒明天九点" → 都要映射到 timer 模块
- 用正则维护成本极高，N 个表达方式就需要 N 个正则

### 4.2 解决方案：TF-IDF + 意图分类（轻量、离线、零成本）

**不需要大模型，不需要 GPU，不需要调 API。用 sklearn（或纯 Python 实现的 TF-IDF）就够了。**

```
训练阶段（一次性）:
  每个模块维护 5-15 条典型表达方式作为"种子样本"
  → 训练一个 TF-IDF 向量化器 + 最近邻分类器

推理阶段（毫秒级）:
  用户输入 → TF-IDF 向量化 → 找最近邻意图 → 提取参数 → 路由
```

### 4.3 种子样本示例

```yaml
# intent_seeds.yaml — 每个意图维护 5-15 条自然语言表达
intents:
  screenshot:
    samples:
      - "截图"
      - "截个图"
      - "帮我截图"
      - "截屏"
      - "screenshot"
      - "capture screen"
      - "拍个屏幕"
      - "把屏幕截下来"
    params: {}  # 后续可加实体提取规则

  compress:
    samples:
      - "压缩这个文件夹"
      - "把 {path} 压缩"
      - "打包 {path}"
      - "解压 {path}"
      - "压缩文件"
    params:
      path: "extract_path"  # 实体提取函数名

  timer:
    samples:
      - "提醒我 {time} {thing}"
      - "明天 {time} 提醒我 {thing}"
      - "设个提醒 {time} {thing}"
      - "倒计时 {minutes} 分钟"
      - "timer"
    params:
      time: "extract_time"
      thing: "extract_remainder"
```

### 4.4 实体提取（不用大模型）

时间提取是唯一需要一点 NLP 的地方，但也不需要用大模型：

```python
# 用 dateparser 或自建规则提取时间实体
# "明天9点" "下午3:30" "5分钟后" "下周一上午10点"
# dateparser 库是纯规则+日历计算，离线可用，零API调用
```

或者更简单的——**让用户填空**：

```
用户: "提醒我明天9点开会"
系统: "已设提醒：明天 09:00 → 开会"
```

甚至可以接受用户分开说：

```
用户: "设个提醒"
系统: ⏰ 请发送：提醒时间 + 提醒内容
      例如：「明天9点 提醒我开会」
用户: "明天9点 提醒我开会"
系统: ✅ 已设提醒：2026-07-03 09:00 → 提醒我开会
```

### 4.5 冷启动策略

种子样本不够时，系统自动收集"未匹配的输入"并提示维护者：

```python
# 记录未匹配的用户输入，供后续扩充样本
UNMATCHED_LOG = "/var/log/executor/unmatched_inputs.log"

# 每周末或手动查看，补充新样本后重新训练
# 重新训练 = 跑一行命令，0.5秒完成
```

### 4.6 为什么这比大模型好

| 对比项 | 大模型 NLU | 本方案 TF-IDF + 规则 |
|--------|-----------|---------------------|
| 成本 | 每次几毛钱 | **零** |
| 速度 | 1-5秒 | **< 10ms** |
| 离线可用 | 不可以 | **完全可以** |
| 确定性 | 不稳定，同样输入不同输出 | **100% 确定** |
| 训练复杂度 | 需要标注数据、调参 | **写 5-15 个例句就行** |
| 扩展新意图 | 需要重新训练或写 prompt | **加 5 个例句 + 一个模块** |

## 五、模块系统设计

### 5.1 模块接口规范

每个模块是一个独立 Python 文件，通过标准输入输出通信：

```python
#!/usr/bin/env python3
"""模块模板 — /opt/executor/modules/example.py"""

import json, sys, shlex, subprocess

def execute(params: dict) -> dict:
    """
    参数：
    - args: list[str] 命令行参数（/命令模式）
    - path: str 操作路径
    - 其他自定义参数
    
    返回：
    - ok: bool
    - msg: str 用户可读的消息
    - data: any 额外数据（选填）
    """
    # 你的逻辑
    return {"ok": True, "msg": "执行成功"}

if __name__ == "__main__":
    try:
        params = json.loads(sys.stdin.read())
        result = execute(params)
        print(json.dumps(result, ensure_ascii=False))
    except Exception as e:
        print(json.dumps({"ok": False, "msg": str(e)}))
```

### 5.2 模块规范约束

| 要求 | 说明 |
|------|------|
| 输入 | 统一 JSON 通过 stdin |
| 输出 | 统一 JSON 到 stdout: `{"ok": bool, "msg": str}` |
| 依赖 | 优先用标准库，第三方依赖写进 `requirements/{module}.txt` |
| 超时 | 系统层 30 秒硬限制，模块自己可设更短 |
| 错误处理 | 不能抛未处理异常，必须 `try/except` 返回 `ok: false` |
| 幂等性 | "查询类"必须幂等，"操作类"尽量幂等或可回滚 |
| 大小限制 | stdout 输出不超过 1MB，大文件写到共享目录返回路径 |

### 5.3 预置模块清单

| 模块 | 功能 | 依赖 | 开发工时 |
|------|------|------|---------|
| screenshot | 截图/区域截图 | 系统 screencapture (macOS) / scrot (Linux) | 1h |
| compress | 压缩/解压 | zip/unzip/tar (系统自带) | 0.5h |
| download | 下载 URL 文件 | curl/wget (系统自带) | 0.5h |
| timer | 一次性定时提醒 | cron + notify | 1h |
| cron | 周期任务管理 | cron | 1h |
| search | 文件搜索 | find/locate (系统自带) | 0.5h |
| clipboard | 剪贴板读写 | pbcopy/pbpaste (macOS) / xclip (Linux) | 0.5h |
| sysinfo | CPU/内存/磁盘 | 标准库 psutil 或 /proc | 0.5h |
| healthcheck | 网站可达性检测 | curl (系统自带) | 0.5h |
| notify | 发送通知（钉钉/企微/Telegram） | curl | 1h |
| csv | CSV 查询/汇总 | Python 标准库 csv | 1h |
| mail | 发邮件 | smtplib (标准库) | 1h |
| api_gateway | 调外部 API 并格式化 | curl/requests | 1.5h |

**以上所有模块的第三方依赖均为零，或仅有极轻量的官方工具。**

### 5.4 模块发现机制

模块即文件，不需要注册：

```
/opt/executor/modules/
├── screenshot.py        # /screenshot → 自动发现
├── compress.py          # /compress → 自动发现
├── timer.py             # /timer → 自动发现
└── ...
```

引擎启动时扫描目录，以文件名（去掉 `.py`）作为指令名。

## 六、安全体系（必须优先考虑）

这是原方案最大缺失。通过消息通道执行系统命令，安全必须在一开始就钉死。

### 6.1 三层防御

```
第一层：指令白名单
  └── 只能执行 modules/ 下已注册的模块
  └── 不能直接执行任意 shell 命令
  └── 模块内部调 subprocess 受参数校验限制

第二层：参数校验
  └── 路径参数：禁止 ../ 等穿越操作
  └── 命令参数：拒绝包含 | ; & ` $ () {} [] 等特殊字符（除非模块白名单）
  └── 类型校验：数字参数必须是数字，URL参数必须符合 URL 格式
  └── 长度限制：单参不超过 256 字符，总参不超过 4096 字符

第三层：审计日志
  └── 记录每条指令：时间 / 用户 / 渠道 / 指令 / 参数 / 执行结果
  └── 日志不可篡改（只追加，定期轮转）
  └── 最近 100 条可通过 /audit 查看（管理员专属）
```

### 6.2 模块沙箱（可选，高危模块启用）

```python
# 沙箱方案一：子进程隔离（默认）
subprocess.run(
    ["python3", "-I", mod_path],  # -I 隔离模式
    input=input_json,
    capture_output=True,
    timeout=30
)

# 沙箱方案二：容器隔离（高安全场景）
# 每个模块运行在临时 Docker 容器中，执行完自动销毁
# docker run --rm --network=none --read-only --memory=256m ...
```

默认使用方案一（零依赖），方案二仅在客户需要高安全级别时启用。

### 6.3 安全底线清单

```
✅ 必须做：
  - 指令白名单（未注册指令不执行）
  - 参数路径穿越检查
  - 审计日志
  - 限频（同一用户每分钟最多 30 条指令）

✅ 强烈建议：
  - 敏感操作二次确认（删除/覆盖/关机等）
  - Telegram 命令模式与自由模式的区分
  - 管理员指令与普通用户指令分离

❌ 绝对不做：
  - 不允许通过指令执行任意 shell
  - 不允许模块加载用户输入作为代码执行（eval/exec）
```

## 七、渠道接入

### 7.1 渠道优先级

| 渠道 | 优先级 | 理由 |
|------|--------|------|
| **Telegram Bot** | ⭐⭐⭐⭐⭐ | 官方 API 免费、稳定、长连接、支持文件/图片/按钮，零封号风险 |
| **企业微信 Bot** | ⭐⭐⭐⭐ | 国内企业常用，官方 API 稳定 |
| **Web 页面** | ⭐⭐⭐ | 辅助管理后台，配置/查看日志 |
| **REST API** | ⭐⭐⭐ | 给技术用户或集成其他系统 |
| **微信个人号** | ⭐ | 仅作为辅助，不依赖，不承诺稳定性 |

### 7.2 Telegram Bot 接入示例（16 行）

```python
"""tg_bot.py — Telegram Bot 接入，零外部依赖（仅 python-telegram-bot）"""

from telegram import Update
from telegram.ext import Application, CommandHandler, MessageHandler, filters
from executor import route  # 上面写的核心引擎

async def handler(update: Update, ctx):
    msg = update.message.text.strip()
    result = route(msg)        # 走同一个 route 入口
    await update.message.reply_text(result.get("msg", "执行成功"))

app = Application.builder().token("YOUR_BOT_TOKEN").build()
app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, handler))
app.run_polling()
```

## 八、部署方案

### 8.1 部署选项

| 方案 | 成本 | 适用场景 |
|------|------|---------|
| 客户本地旧电脑/树莓派 | 0-50元/月电费 | 客户自己有空闲设备 |

## 九、适用场景与不适用场景（诚实划界）

### ✅ 适用场景

| 场景 | 示例 | 匹配度 |
|------|------|--------|
| 定时执行固定操作 | 每天10点拉销售数据发群 | ⭐⭐⭐⭐⭐ |
| 查询类操作 | 查库存、查服务器状态、查汇率 | ⭐⭐⭐⭐⭐ |
| 文件操作 | 压缩、搜索、格式转换、备份 | ⭐⭐⭐⭐⭐ |
| 简单的监控告警 | 网站挂了发通知、磁盘满告警 | ⭐⭐⭐⭐⭐ |
| 数据处理管道 | CSV 汇总 → 发邮件 | ⭐⭐⭐⭐ |
| 内部运维工具 | 重启服务、查看日志、清理缓存 | ⭐⭐⭐⭐ |

这些场景的共同点：**操作流程确定、输入输出可枚举、不需要判断理解。**

### ❌ 不适用场景

| 场景 | 原因 |
|------|------|
| 复杂推理 | "分析一下这个季度为什么销量下滑" — 没有 AI 做不到 |
| 创意生成 | "帮我写一封促销邮件" — 模板可以，但创意不行 |
| 开放域问答 | "什么是区块链" — 没有知识库 |
| 非结构化信息提取 | "从这张发票图片里提取金额" — 没有 OCR |
| 需要语义理解的多人对话 | "他跟你说那个事你帮我问一下" — 无法理解指代 |
| 需要情绪感知的交互 | 客户骂人了要安抚 — 做不到 |

**诚实比什么都重要。** 明确告诉客户什么能做、什么不能做，比硬撑着接单然后交付不了强一百倍。

## 十一、商业模式建议

### 11.1 核心定位（诚实的）

> **这不是一个"卖产品"的生意，这是一个"卖交付"的生意。**
> 本质是：**低成本的定制自动化服务。**

### 11.2 收费模式

| 模式 | 定价 | 说明 |
|------|------|------|
| **一次性搭建费** | 500-2000元 | 根据场景复杂度，包含 1-3 个模块开发 + 部署 |
| **月度维护费** | 100-300元/月 | 运行保障 + 故障排查 + API变化适配 |
| **年度套餐** | 1000-3000元/年 | 搭建费打折 + 全年维护 |
| **年付** | 3000-5000元/年 | 适合稳定需求的客户 |

**为什么比原方案定价低：**
- 原方案 500-2000 元/模块 + 200-500 元/月，对小微企业偏贵
- 小企业愿意为自动化花 100-300 元/月，超过就开始算账对比了
- 我们的成本极低，薄利也能活
- 真正的壁垒不是价格，是**响应速度和服务质量**

### 11.3 利润模型

```

一个模块的定价：500-2000元（一次性）
一个客户的月维护：100-300元/月

  10 个客户 × 200元/月 = 2,000元/月（副业收入）
  30 个客户 × 200元/月 = 6,000元/月（不错的兼职）
```

## 十二、总结

### 这个方案是什么

```
✓ 纯指令执行系统 — 说啥干啥，不猜不想
✓ 零大模型依赖 — 不调任何 LLM API，不需要 GPU
✓ 有自然语言理解能力 — 不用大模型的轻量 NLU，用户可以说人话
✓ 安全优先 — 白名单 + 参数校验 + 审计日志
✓ 模块化积木 — 每个功能独立，可加可删
✓ 渠道灵活 — Telegram 为主，多渠道可选
✓ 一个人可跑通 — 不需要团队、融资、办公室
```

### 这个方案不是什么

```
✗ 不是大模型 Agent
✗ 不是 SaaS 平台
✗ 不是通用产品
✗ 不需要 GPU
✗ 不需要烧 API token
✗ 不需要融资
```

### 与原方案的关键差异

| 原方案 | 本方案 |
|--------|--------|
| 只支持 `/` 命令，生硬 | 支持自然语言，自动映射 |
| 完全没有安全设计 | 白名单 + 参数校验 + 审计日志三层防御 |
| 微信为主要渠道（风险高） | Telegram 为主，多渠道可选 |
| 定价偏高（500-2000/模块+200-500/月） | 更务实的 100-300 元/月 |
| 商业模式像外包（卖工时） | 商业模式像服务（卖自动化场景） |
| 回避了局限性 | 诚实划界，告诉什么做不了 |

### 一句话

> **不做"什么都会但靠不住"的AI，做"只会几件事但绝对可靠"的指令执行器。**  
> **而且不需要大模型，不需要 GPU，联网就能跑。**
