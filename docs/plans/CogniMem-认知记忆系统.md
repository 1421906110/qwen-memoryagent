# 🧬 CogniMem — 认知记忆系统设计
> 从"存储"到"思考"：下一代 AI Agent 记忆架构

---

之前那份报告是从**存储角度**写的——怎么存、怎么搜、怎么省 token。

不对。真正聪明的记忆不是数据库，是**思维方式**。

所以我重新想了这个问题：**如果 Agent 像人一样记忆，应该怎么设计？**

---

## 1. 先搞清问题：为什么现有方案都不行

| 方案 | 本质 | 致命问题 |
|------|------|---------|
| **RAG + Vector DB** | 文档搜索换皮 | 搜到啥用啥，没判断力 |
| **Memanto** | 带 TTL 的 Key-Value | 平的、被动的、不会思考 |
| **Claude Memory** | 事实列表塞 Prompt | 粗暴，全靠上下文窗口大 |
| **LangChain Memory** | Buffer + Summary | 要么全塞要么乱压缩 |
| **Mem0/GitMemory** | 有点分级 | 还是存→搜逻辑，不思考 |

**共同病根：它们把记忆当"文件"管，不是当"知识"管。**

---

## 2. 核心理论：记忆不是存储，是推理

### 2.1 三条第一性原理

```
① 记忆的本质是压缩
   存储 = 决定什么值得记住
   忘记 = 决定什么可以丢掉
   真正的智能 = 知道区别

② 知识来自矛盾
   A 和 B 矛盾 → 才知道哪个更可信
   从不矛盾的知识 → 已经固化为信念
   信念 = 经过足够多挑战后依然成立的信息

③ 回忆是重建，不是回放
   每次回忆都在"重新理解"过去
   同一件事，不同上下文 → 不同理解
```

### 2.2 认知记忆模型 (Novel)

区别于所有现有系统的核心设计：

```
传统系统: 存[文本] → 搜[文本] → 塞[文本] → Agent 自己看着办
    我:    存[事实图] → 推理[事实间的关系] → 生成[Agent 需要的理解]
```

## 3. 架构设计

### 3.1 三大脑区

```
┌──────────────────────────────────────────────────────┐
│                   CogniMem Core                       │
├────────────┬───────────────────┬─────────────────────┤
│  海马体     │     新皮层         │     前额叶          │
│ (短期记忆)  │   (长期知识)       │   (执行控制)        │
├────────────┼───────────────────┼─────────────────────┤
│ 缓存上下文  │ 事实网络           │ 路由决策            │
│ 当前会话   │ 信念系统           │ 冲突检测            │
│ 最近交互   │ 技能记忆           │ 压缩调度            │
│            │ 时序事件           │ 预加载决策          │
└────────────┴───────────────────┴─────────────────────┘
```

### 3.2 事实网络 — 核心创新

**不是存文本，是存"事实"及其"关系"：**

```json
{
  "fact_id": "f_001",
  "content": "用户喜欢喝冰美式",
  "type": "preference",
  "confidence": 0.85,
  "evidence": [
    {"source": "对话_20260701_1532", "statement": "给我来杯冰美式"},
    {"source": "对话_20260701_1600", "statement": "热的喝不惯"}
  ],
  "contradictions": ["f_089"],     // 如果有矛盾记录
  "connected_facts": ["f_002"],    // 相关事实
  "context_tags": ["coffee", "daily_habit"],
  "importance": 0.7,
  "encoding": "raw"                 // raw|compressed|core
}
```

**关键区别：**
- 传统：存"用户喜欢喝冰美式" 这条文本
- CogniMem：存"用户喜欢喝冰美式" **这个事实** + **支持证据链** + **置信度** + **关系网络**

## 4. 核心算法

### 4.1 三元记忆引擎 (Tri-Memory Engine)

这是整个系统的核心创新。

```
写入任何信息时，系统自动拆分为三元组:

         [实体] ────[关系]──── [实体]
        "用户"     "喜欢"     "冰美式"

每条记忆 = 一组三元组 + 元数据 + 证据链

为什么拆成三元组?
  1. 精确检索: "谁喜欢什么" → 直接查图, 不用语义搜索
  2. 关系推理: A→B, B→C → A→C (传递性推理)
  3. 矛盾检测: "用户喜欢冰美式" vs "用户说冰水难喝" → 自动发现冲突
  4. 极致压缩: 存100个三元组 ≈ 2KB, 覆盖1000条对话的信息量
```

**比 Vector Search 省多少？**

| 方式 | 1000条对话 | Token 消耗 |
|------|-----------|-----------|
| Vector Search (全量召回) | 全量 Embedding | ~50,000 tokens |
| 三元组精准匹配 | 只查目标节点 | ~500 tokens |
| **节省** | | **~99%** |

### 4.2 置信度贝叶斯更新

```
不是简单算分，是贝叶斯更新：

P(事实为真 | 新证据) = P(新证据|事实为真) × P(事实为真)
                      ──────────────────────────
                          P(新证据)

简化实现:
  初始置信度 = 0.6 (默认)
  每次被证实  += 0.1
  每次被质疑  -= 0.15
  置信度 > 0.9 → 提升为核心信念 (L3)
  置信度 < 0.2 → 标记为不可靠，可清理
  置信度 < 0.1 → 自动删除

Agent 知道什么:
  "我肯定用户喜欢冰美式" (conf=0.95)
  "我怀疑用户可能想戒咖啡" (conf=0.35)
  Agent 能表达"我不确定"，而不是瞎编
```

### 4.3 矛盾驱动学习 (Contradiction-Driven Learning)

这是最创新的部分——现有系统全都没有。

```
检测到矛盾时:
  ┌──────────────────────────────────────────────────┐
  │ 新信息: "用户说最近在戒咖啡"                      │
  │ 旧事实: 用户喜欢喝冰美式 (conf=0.85)             │
  │                                                   │
  │ 1. 不覆盖! 创建矛盾记录:                          │
  │    {fact_a: "喜欢冰美式", fact_b: "在戒咖啡",     │
  │     detected_at: now, resolution: "pending"}      │
  │                                                   │
  │ 2. 降低双方置信度:                                │
  │    "喜欢冰美式": 0.85 → 0.65                      │
  │    "在戒咖啡": 初识置信度 0.6                      │
  │                                                   │
  │ 3. Agent 下次提到咖啡时, 触发矛盾提醒:            │
  │    "我之前了解到你喜欢冰美式, 但你最近说在戒咖啡,  │
  │     能确认一下现在的情况吗?"                      │
  │                                                   │
  │ 4. 用户确认后: 一方置信度上涨, 另一方下降或删除   │
  └──────────────────────────────────────────────────┘

没有矛盾 → 死知识
有矛盾 → 动态知识
动态知识 → 更聪明的 Agent
```

### 4.4 主动遗忘 (Active Forgetting)

人脑最被低估的能力——**知道要忘什么**。

```
遗忘触发条件 (任一):
  ├─ 置信度 < 0.2 且 30天未被引用
  ├─ 被矛盾证据推翻 且 用户确认了新事实
  ├─ 重要性 < 0.3 且 已过 TTL × 3
  └─ 存储压力触发 (达到容量阈值的 90%)

遗忘不是删除，是降级:
  原始事实 → 只保留三元组骨干 (去掉证据链和元数据)
  三元组骨干 → 只保留"有这个事"的标记 (用于防重复)
  标记 → 彻底删除

Token 回收 = 被遗忘的记忆恢复的空间
```

### 4.5 睡眠期记忆整合 (Memory Consolidation)

模拟人脑睡眠时整理记忆的机制。

```
执行时机: Agent 空闲 > 5分钟 / 显式请求

整合内容:
  1. 重复检测: 同一事实的不同表述 → 合并, ref_count++
  2. 矛盾清理: 用户已确认的 → 执行置信度更新
  3. 模式发现: 长期模式 → 提升为"习惯性信念"
     "用户每次周一问项目进度" → schedul: weekly_report
  
  4. 降级策略:
     访问少 + 重要性低 → L1 → L2 → L3 或删除
     访问多 + 置信度高 → 稳定持久存储
```

## 5. 创新亮点汇总

| 创新点 | 现有系统 | CogniMem | 突破 |
|--------|---------|----------|------|
| **存储单元** | 文本/向量 | 三元组事实 | 可推理、可追溯 |
| **召回方式** | 语义搜索 | 图遍历 + 置信度排序 | 省99% Token |
| **矛盾处理** | 无 / 后写覆盖 | 矛盾记录 + 主动询问 | Agent 会反思 |
| **置信度** | 无 / 固定 | 贝叶斯动态更新 | Agent 知道"不确定" |
| **主动遗忘** | 固定 TTL 删除 | 智能降级 | 越用越精准 |
| **记忆整合** | 无 | 空闲期自动整理 | 自我优化 |
| **Token 效率** | 基线 | ~99% 召回节省 | 长期优势碾压 |

| 维度 | HMS (旧) | CogniMem (新) | 进步 |
|------|---------|---------------|------|
| 设计出发点 | 省 Token、省存储 | 模拟认知、更聪明 | 升维 |

| Token 节省 | ~70% | ~99% | 量级差距 |

## 8. 争议性讨论区

### 8.1 三元组是不是太简单了？

看起来简单。但：
- 整个知识图谱领域的基础就是三元组
- 复杂知识 = 多个三元组的组合
- 简单 = 可靠 = 容易推理 = 容易验证
- 别为了看起来高级而做复杂

### 8.2 置信度贝叶斯更新准确吗？

不完美，但**足够用**。
- 精确贝叶斯计算很复杂
- 我们用的是简化版（线性近似）
- 目的是让 Agent 有"确定性"的概念，不是精确求概率
- 0.2 和 0.8 的区别比 0.73 和 0.74 有意义得多

### 8.3 CogmiMem 比现在的好多少？

不是"好多少"，是**根本不是一个东西**。
- 现有方案：存文本、搜文本、塞文本
- CogniMem：存知识、推理知识、生成理解
- 就像文件系统 vs 关系数据库——看着都存数据，能力差几个维度

---

> **核心一句话：**
> 不是做一个更好的记忆存储，而是让 Agent 拥有**真正的认知能力**——记住什么、忘记什么、相信什么、怀疑什么。
