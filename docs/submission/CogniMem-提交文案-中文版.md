## 🧠 核心能力：记忆系统

### 存的是结构，不是文本

大多数记忆系统直接把对话原文存起来，召回时靠关键词硬匹配。这种方式有两个致命问题：

1. **召回质量差**——"冰美式"和"冷萃"在关键词层面完全不相关，但实际是同类偏好，搜不到
2. **无法推理**——存了一大段文本，但程序无法理解"用户到底喜欢什么"

CogniMem 不同。它把每句话实时拆解为 **SPO 三元组（主体-谓词-客体）**，构建可推理的结构化知识网络：

| 你说的话 | CogniMem 提取的结构 |
|:---------|:-------------------|
| "帮我看看上次那个咖啡店几点开门来着" | `(我, 问过, 咖啡店营业时间)` |
| "哦对了，我不喝含糖的" | `(我, 不喜欢, 含糖饮料)` |
| "发我邮箱吧，xxx@gmail.com" | `(我, 邮箱, xxx@gmail.com)` |
| "我每周三下午有空" | `(我, 空闲时间, 周三下午)` |
| "上次那个方案客户不太满意，改成B版吧" | `(方案A, 客户反馈, 不满意)`, `(当前方案, 切换到, 方案B)` |

三元组结构让机器能理解关系：谁是主体？什么动作？作用于什么对象？而不是把"我住在北京"当成一个黑盒字符串。

### 提取成本趋近于零

如果每个句子都调大模型提取，成本不可接受。CogniMem 采用三层递进策略：

```
第一层：规则提取（0 token）
  → 正则模板匹配常见句式：
    "我喜欢X" → (用户, 喜欢, X)
    "我不喜欢X" → (用户, 不喜欢, X)
    "我叫X" → (用户, 名字, X)
    此层覆盖约 70% 日常表达

第二层：缓存复用（0 token）
  → 同用户相似表达命中缓存，直接返回上次提取结果
  → 不同用户相同句式共享模板，无需重复解析

第三层：LLM 提取（调用 Qwen）
  → 以上两层都处理不了的复杂句式才调大模型
  → 实际调用量不足全部的 10%
```

### 自动发现矛盾

记忆系统最怕存了互相矛盾的信息——昨天说"喜欢冰美式"，今天说"不喜欢冰美式"，系统该信哪条？

CogniMem 用三层矛盾检测来解决：

| 层级 | 检测方法 | token 消耗 | 工作逻辑 |
|:----|:---------|:---------:|:---------|
| **L1：否定词匹配** | Jaccard 相似度 + 否定词表 | **0 token** | "喜欢" vs "不喜欢" → 提取否定前缀 → 判定矛盾 |
| **L2：语义相似度** | Embedding 余弦相似度 | **0 token** | "喜欢咖啡" vs "喜欢火锅" → 向量距离远 → 不同偏好，不是矛盾 |
| **L3：LLM 裁决** | 交给 Qwen 语义判断 | **少量 token** | 前两层都无法确定时，由大模型做最终判断 |

**中性谓词自动跳过**：`(用户, 请求, 读文件)` vs `(用户, 请求, 搜网络)` → 请求类动作被视为中性，不会产生矛盾误报。

**跨类别偏好感知**：`(用户, 喜欢, 咖啡)` vs `(用户, 喜欢, 火锅)` → 这是两个独立的偏好维度，不是矛盾。同类别偏好冲突才需要关注。

### 碎片自动归纳

零散的同类信息日积月累，CogniMem 会自动归纳为高层概念：

> 某天用户说"今天喝了杯冰美式"
> 过几天说"热美式是我的最爱"
> 又过几天说"冷萃咖啡很好喝"
>
> 系统自动识别出三条事实共享 `(用户, 喜欢, ?)` 模式，且宾语同属"咖啡"语义场
> → 自动归纳为 **"用户喜欢喝咖啡"** 这一抽象信念（core_belief）

归纳过程在系统空闲时自动触发，无需人工干预。

### 科学遗忘机制

不是所有记忆都值得永远保留。CogniMem 借鉴艾宾浩斯遗忘曲线：

```
half_life = 24h × (1 + √access_count)

置信度衰减公式：
  - 从未被召回的记忆：max(0, 1 − (存在时间/24h)^0.7)
  - 有被召回的记忆：初始置信度 × 2^(−经过时间/half_life)
```

简单说：**越常被提起的事，忘得越慢；提过一次再没说过的事，自然消退。**

每条记忆从创建到最终衰减的完整生命周期可追溯：

```
created(0.6) → confirmed(0.7) → challenged(0.5) → confirmed(0.8) → decayed(0.3) → pruned
```

每次变化的时间、原因、新旧置信度都有记录，通过 `/versions/{id}` 端点可查。

### 四层召回流水线

当程序需要查询记忆时，按以下路径依次尝试：

```
用户提问
  ↓
L0 精确缓存：问过一模一样的问题？→ 直接返回上次结果（0 token）
  ↓（未命中）
L1 Deny 过滤：问题是否与已知事实矛盾？→ 排除冲突信息
  ↓（通过）
L2 Embedding 召回：向量相似度匹配最相关的 N 条事实
  ↓（召回结果）
L3 图谱漫步：从召回结果出发，沿 SPO 关系图扩展关联事实
  ↓
最终输出：综合评分最高的 K 条记忆，注入上下文
```

## 四大设计原则

### 1️⃣ 🧠 更智能

CogniMem 不只是记忆系统，它包含一个完整的 Agent 引擎：

**12 个内置工具：**
| 工具 | 用途 |
|:----|:------|
| web_search | 联网搜索最新信息 |
| web_fetch | 抓取指定网页内容 |
| read_file | 读取本地文件 |
| write_file | 写入文件 |
| shell | 执行命令 |
| python_repl | 运行 Python 代码 |
| execute_code | 执行代码片段 |
| visit_url | 访问 URL |
| memory_recall | 查询记忆 |
| memory_diagnose | 诊断记忆健康状况 |
| memory_status | 查看记忆统计 |
| memory_forget | 删除指定记忆 |

**交互式仪表盘：**
- 4 个指标卡：总记忆数、抽象概念数、活跃偏好数、需关注项
- 系统健康卡：点击弹出 5 维度详情模态框（DB 连接、LLM 状态、配置完整性、工具可用性、API 错误率）
- 记忆分布图：doughnut 图展示各类事实占比（preference/fact/action/goal/decision/observation）
- 增长趋势图：累计记忆量随时间变化曲线
- 关键洞察：自动生成的记忆分析摘要（最多类型、最新记忆、低置信度告警等）
- 记忆分类：各类别水平柱状图 + 百分比
- 活动日志：滚动显示最近记忆事件

**知识图谱：**
- 力导向图可视化，节点 = 实体，边 = 关系
- 8 种语义类型分别用不同颜色标识（preference/fact/action/goal/decision/observation/entity/abstraction）
- 支持类型筛选（checkbox）、节点点击查看详情、拖拽、缩放
- 抽象节点用虚线边框标识，视觉上区分原始事实与高层归纳
- 右侧详情面板：显示节点的字段、关系列表、关联事实

**目标驱动的 Agent 引擎：**
- 收到用户请求后自动规划步骤（如：先搜索 → 再读取 → 最后分析）
- 每轮迭代自我检查：目标是否完成？是否需要更多工具调用？
- 工具调用失败自动纠错（如搜索无结果 → 换关键词重试）
- 每次任务完成后自我反思，记录经验教训到 lessons.json

### 2️⃣ 💰 更省 Token

| 场景 | 处理方式 | token 消耗 |
|:----|:--------|:---------:|
| 问候语"你好""再见" | is_simple 路由检测 → bypass 整个 Agent 系统 → 直接流式回复 | **0** |
| "我喜欢喝冰美式" | 正则规则直接拆解 SPO，不需要 LLM 参与 | **0** |
| 5 分钟内问过同样问题 | L0 缓存命中，直接返回上次结果 | **0** |
| "喜欢" vs "不喜欢" 矛盾检测 | L1 否定词词法对比，不需要 LLM | **0** |
| 向量相似度对比 | L2 Embedding 计算，数据库内完成 | **0** |
| 复杂句式 / 跨事实归纳 / 语义模糊判断 | 至此才调用 Qwen3.7-Plus | **少量** |

### 3️⃣ ⚡ 更省资源

- **存储层**：PostgreSQL + pgvector，启动耗时不到 1 秒。不依赖外部缓存服务，单机即可运行
- **自动维护**：系统空闲 5 秒后自动触发 consolidation 任务——合并重复事实、归纳同类碎片、解析矛盾对、衰减旧记忆
- **上下文管理**：Agent 做多步任务时会积累大量中间消息。CogniMem 实时监控上下文大小，超过 24K token 时自动裁剪最早的无用轮次
- **稳定性**：
  - DB 连接池失效后自动检测 + 重建，不崩溃
  - 所有 LLM 调用带 3 次自动重试 + 指数退避
  - 全局异常捕获，所有端点统一返回结构化 JSON，不裸抛 500
  - systemd 开机自启，ECS 重启后服务自动恢复
  - HTML 模板带 mtime 缓存键，修改文件后自动刷新，无需重启服务

### 4️⃣ 🚀 算法更创新

| 创新点 | 说明 |
|:------|:------|
| **矛盾驱动学习** | 不是被动忽略矛盾——检测到矛盾后主动向用户提问："你之前说喜欢冰美式，现在说不喜欢，是变了吗？" 通过用户确认解决矛盾，提升认知准确度 |
| **三元组结构推理** | 扁平文本只能全文搜索；三元组可以组合查询：搜"住在北京的程序员"→ `(?, 住在, 北京)` ∩ `(?, 职业, 程序员)` → 精确命中 |
| **噪音自动过滤** | curl、wget、httpie、ping、traceroute 等系统命令自动跳过，不收入记忆库；web_fetch 结果属于中间数据，无记忆价值，同样跳过；同一轮对话内的多次 web_search 只存第一次结果 |
| **跨类别偏好识别** | "喜欢咖啡"和"喜欢火锅"是两个独立偏好维度，不误判为冲突。只有同类别的相反偏好（如"喜欢冰美式" vs "不喜欢冰美式"）才触发矛盾告警 |
| **科学遗忘曲线** | 不只是"超过 N 天就删"的粗暴逻辑——访问频率越高，half_life 越长，记忆越持久。从"鱼的记忆"变成有层次的长期记忆 |
| **主动学习** | 检测到知识空白或不确定时，主动向用户提问（Active Learning），而不是沉默忽略 |

## 技术栈

| 层 | 选型 | 选型理由 |
|:--|:-----|:---------|
| **大模型** | Qwen3.7-Plus + Qwen3.6-Flash (DashScope) | 前者负责推理/提取/判断，后者负责快速响应；1M 上下文窗口 |
| **服务端** | Python 3.14, FastAPI 0.115+, Uvicorn | Python 生态成熟，FastAPI 性能接近 Go，开发效率高 |
| **持久化** | PostgreSQL 14 + pgvector | 关系数据库 + 向量搜索一体化，免去维护两套存储 |
| **Agent 引擎** | 目标驱动循环 + 预规划 + 自反思 | 自主规划步骤、执行、纠错，不是简单的"调 API" |
| **记忆引擎** | CogniMem（三层提取 + 艾宾浩斯衰减 + 矛盾检测 + 归纳抽象）| 核心自研 |
| **前端** | 原生 JavaScript, Chart.js, Canvas | 零框架依赖，页面轻量，直接内嵌在 FastAPI 模板中 |
| **部署** | 阿里云 ECS (Ubuntu 22.04), systemd 自启 | 比赛指定平台 |

### 架构示意

```
用户浏览器 → FastAPI（15+ 端点）
  → Agent 引擎（12 工具 + 目标驱动 + 自反思）
    → CogniMem 核心（三层提取/矛盾检测/艾宾浩斯衰减/碎片归纳）
      → PostgreSQL + pgvector（SPO 事实/版本链/向量索引）
        → Qwen3.7-Plus + Qwen3.6-Flash（DashScope）
```

三页面统一入口：
- `http://.../` → 聊天界面，对话 + 记忆召回
- `http://.../dashboard` → 仪表盘，统计 + 管理
- `http://.../graph` → 知识图谱，关系可视化

共享同一 localStorage key 同步 agent 选择，页面间切换无缝。

## 主要挑战与解决

| 挑战 | 具体问题 | 解决方案 |
|:-----|:---------|:---------|
| **记忆噪音** | curl、wget、ping 这些系统命令不应该被当成"用户事实"存进记忆库。同一对话里的多次 web_search 会产生大量重复的"用户请求了搜索"记录 | 三步过滤：1) shell 命令以 curl/wget/httpie/ping/traceroute 开头的跳过 2) web_fetch 完全跳过（中间数据，无记忆价值）3) 同一对话只存第一次 web_search |
| **首句空白** | 新建 Agent 后第一句对话返回空内容，从第二句开始才正常 | 缺少 QWEN_FAST_MODEL 配置导致 fast model 默认值不兼容 DeepSeek/Qwen。在 .env 中显式配置即可 |
| **图谱初始化无数据** | 进入图谱页面时默认用 localStorage 里的 hardcode "default" agent_id，如果 default 没有数据就显示空白 | 改为优先从 API `/agents` 拉真实 agent 列表，合并 localStorage，选择有数据的 agent 自动加载 |
| **上下文爆窗口** | Agent 做多轮工具调用后 openai_messages 累积到数万 token，超过 LLM 上下文窗口 | 每次迭代前检查总 token 数，超过 24K 时自动裁剪最早的系统消息和工具结果，保留最近的对话轮次 |
| **DB 连接池毒化** | PostgreSQL 重启后已有的连接变成坏连接，后续请求全部报错 | 每次请求前执行 `SELECT 1` 探活，发现坏连接自动替换。独立健康检测线程定期轮询 |
| **三元组类型缺失** | dashboard 图表和图谱只展示 6 种类型，action 类型的记忆（行为记录）完全不可见 | 图表组件、图谱筛选器、类型颜色映射全部补上 action 类型 |
