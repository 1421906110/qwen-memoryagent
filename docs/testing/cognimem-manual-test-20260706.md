## 发现问题

### 🟡 发现 1: 搜索工具调用过多

- **2.1 测试** tools=17，手册预期 2-8
- **根因**: agent 在搜索后继续做了额外操作（可能调了 file ops 或 memory）
- **影响**: token 浪费，响应时间延长
- **建议**: 检查 system prompt 早停逻辑，或降低 max_iterations

### 🟡 发现 2: "我叫张三，住在北京" 仅提取 1 个 fact

- **预期**: 2 个（名字 + 住址）
- **实际**: 1 个 fact
- **位置**: extractor 规则匹配
- **影响**: 含两个陈述的复合信息丢失一半

### 🟡 发现 3: 单 worker uvicorn 无法承受并发 LLM 请求

- **表现**: 发送 1-2 个 LLM 请求后，服务停机
- **根因**: uvicorn 单 worker + LLM 同步阻塞，后续请求超时
- **日志**: 无 ERROR/Traceback — 是优雅 shutdown 还是 OOM 需进一步调查
- **影响**: 无法运行完整测试套件（2.5-2.9, 3.x, 4.x, 5.x, 8.2-8.4 全部跳过）
- **建议**: 增加 workers=2 或启动独立 CogniMem 引擎进程

**阻塞原因**: 服务为单 worker uvicorn，LLM 请求同步阻塞导致 8GB Intel Mac 无法承载并发，请求超时后服务 shutdown。

**解决建议**: 
1. 启动时增加 `--workers 2 --limit-concurrency 5`
2. 或分离 CogniMem 引擎到独立进程（8001 端口）
3. 或在测试时串行发请求（间隔 >30s）
