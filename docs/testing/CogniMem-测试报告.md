## 三、🐛 Bug 详细分析

### Bug #1 🔴 严重：否定词「不」被完全忽略

**触发条件：** 输入 `"用户不喜欢喝冰美式"`

**实际行为：**
- 提取为 `用户 | 喜欢 | 喝冰美式`（predicate 仍是"喜欢"）
- 追加到已有事实的 evidence 数组中
- **contradictions_detected=0**（完全没检测到矛盾）
- 置信度不变（仍 0.57）
- 证据数组同时包含："用户喜欢喝冰美式" 和 "用户不喜欢喝冰美式" — 两条矛盾的陈述共存

**预期行为：**
- 方案 A：提取为 `用户 | 不喜欢 | 喝冰美式`（独立事实）
- 方案 B：检测到 L1 deny，contradictions_detected=1，confidence 受惩罚

**根因推测：** 规则提取器对否定词「不」无处理，直接将其视为普通文本，匹配到同主语+同谓语+模糊宾语，做了证据合并。

**影响范围：** 所有带「不」的否定句全部被当作肯定句吸收，记忆系统会学到错误的用户偏好。

---

### Bug #2 🔴 严重：MemoryAgent 图谱端点 500

**触发条件：** `GET /memory-graph?agent_id=default`

**实际行为：**
```
HTTP 500 Internal Server Error
（空响应体）
```

**预期行为：** 返回包含节点、边、统计数据的 JSON

**影响范围：** Web UI 的图谱页面无法加载，影响可视化和调试。

---

### Bug #3 🟡 中等：主动学习将无关事实误报为矛盾

**触发条件：** 用户有「喜欢喝美式」「喜欢冷萃咖啡」「喜欢吃火锅」「喜欢麻辣烫」

**实际输出：**
```
💬 你提到过「用户喜欢冷萃咖啡」，但同时也说过「用户喜欢吃麻辣烫」。这两者好像不太一致
💬 你提到过「用户喜欢热美式」，但同时也说过「用户喜欢吃麻辣烫」。这两者好像不太一致
```

**预期行为：** 「冷萃咖啡 vs 麻辣烫」「热美式 vs 麻辣烫」不属于矛盾，不应生成主动学习问题。

**根因：** LLM 矛盾判断时 predicate（喜欢）相同就触发矛盾检测，忽略了 object 所属不同类别（咖啡 ≠ 美食）。

**影响范围：** 用户被大量无意义的矛盾问题打扰，降低体验。

---

### Bug #4 ⚠️ 轻微：超长文本 subject 提取为英文「user」

**触发条件：** 500 次重复中文「测试长文本输入。」

**实际行为：**
```json
{"subject": "user", "predicate": "said", "object": "测试长文本输入测试长文本输入测试长文本输入..."}
```

**预期行为：** subject 应为「用户」（中文），predicate 应是具体的陈述内容。

**影响范围：** 中英文不一致，长文本提取结果无意义。

---

### Bug #5 🟡 中等：引擎稳定性差，频繁崩溃

**现象：** 运行一段时间后（或某些请求后），`:8001` 进程消失，curl 返回 exit code 7（Connection refused）。

**复现：** 连续执行 3-5 个 curl 请求后即可能发生。

**根因推测：** 可能是异步任务（auto-consolidation）导致的未捕获异常，或 Uvicorn 进程被会话管理器收割。

**影响：** 每次崩溃后需手动重启，不适合生产。

---

### Bug #6 🟢 轻微：L2 间接冲突惩罚力度不符预期

**预期（手册）：** L2 conflict 惩罚 0.08
**实际：** confidence 从 0.57 降至 0.52（降 0.05）

**影响：** 低风险，实际是 base_confidence 不同导致的计算差异。如需精确对齐需检查罚分公式。

## 八、引擎稳定性补充记录

> 测试中发现 `:8001` 引擎存在严重的进程不持久问题。

### 8.1 启动方式对比

| 方式 | 命令 | 存活时长 | 备注 |
|------|------|---------|------|
| ❌ nohup 后台 | `nohup uvicorn main:app --port 8001 &` | 30秒~3分钟不等 | 多次测试中反复崩溃 |
| ❌ nohup + disown | `nohup ... & disown` | 同上 | 同样不稳定 |
| ✅ Python 内嵌启动 | `python -c "uvicorn.run('main:app', port=8001)" &` | 存活待验证 | 当前使用中 |

### 8.2 崩溃特征

- **无声崩溃**：进程直接消失，日志无报错、无 traceback、无 segfault
- **触发条件**：连续 3~5 个 curl 请求后高概率崩溃
- **时间规律**：启动后约 1~2 分钟内（auto-consolidation 触发前后）
- **不影响 9999**：MemoryAgent 仪表盘（uvicorn 运行）稳定持续运行

### 8.3 可能原因推测

1. **auto-consolidation 异步异常**：启动日志显示 `🌙 Auto-consolidation triggered for 'default' (idle: 1782942182s)`，如果整合过程中有未捕获异常会导致进程退出
2. **nohup 会话管理**：MacOS 下 nohup 子进程可能被终端会话管理器回收
3. **uvicorn 单Worker 模式**：没有 --reload 或 workers=N，异常即死

### 8.4 建议

- 加全局异常捕获（try/except 包裹 consolidate 逻辑）
- 改用 `python -c "uvicorn.run(...)"` 启动，或加 `--reload` 参数
- 或加 systemd/launchd 自动重启
